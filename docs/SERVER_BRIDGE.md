# Standalone Voice Bridge

Этот документ описывает проект легитимного серверного моста (Paper Plugin) для безопасного подключения внешних (Standalone) клиентов к Simple Voice Chat.

## Почему не работает прямое подключение?

Как описано в [PROTOCOL.md](PROTOCOL.md), обычный клиент Minecraft не может начать UDP-сессию, просто зная IP и порт. Для подключения необходимы:
1. **Идентичность (UUID)** — уникальный идентификатор игрока, признанный сервером.
2. **Секрет (Secret)** — короткоживущий криптографический ключ, выданный сервером для конкретной сессии.
3. **Параметры сессии** — кодек, MTU, флаги групп, которые сервер согласовывает с клиентом.

В официальном клиенте эти данные передаются по защищенному каналу Minecraft (Custom Payload) в пакете `SecretPacket`. Публичный API Simple Voice Chat (версия 2.6.x) намеренно не предоставляет способа запросить этот секрет извне, чтобы предотвратить подмену личности и несанкционированный доступ.

## Архитектура безопасного моста

Чтобы standalone-клиенты (Windows и Android) могли работать, серверный плагин должен выполнять роль доверенного посредника, не нарушая модель безопасности SVC. Мы используем модель **одноразовых токенов подключения (OTP)**, привязанных к UUID игрока.

### 1. Жизненный цикл одноразовых токенов

Токен — это криптографически безопасная случайная строка, которая связывает предстоящее внешнее подключение с уже аутентифицированным UUID игрока.

**Ограничения токена:**
- Одноразовое использование (сгорает сразу после успешного обмена на секрет SVC).
- Короткий срок жизни (например, 2 минуты).
- Привязка к одному конкретному UUID.
- Ограничение на количество активных токенов для одного игрока.

### 2. Комбинированная выдача токенов

Мост поддерживает два способа выдачи токенов, оба из которых требуют, чтобы игрок уже был авторизован сервером Minecraft:

#### Способ А: Автоматическая выдача
1. Игрок заходит на сервер через обычный Minecraft-клиент.
2. Плагин перехватывает событие входа (PlayerJoinEvent).
3. Плагин автоматически генерирует токен для этого игрока.
4. Плагин отправляет токен игроку в чат в виде кликабельного сообщения или `svc://` URI (которое можно отсканировать QR-сканером Android-клиента).

#### Способ Б: Ручная выдача по команде
1. Игрок находится на сервере.
2. Игрок вводит команду `/voice standalone`.
3. Плагин отзывает старые неиспользованные токены этого игрока, генерирует новый и выводит его в чат.

*Внимание:* Плагин **никогда** не должен выдавать токен неавторизованному внешнему TCP/HTTP-запросу. Внешний запрос может только *обменять* уже существующий токен на секрет SVC.

### 3. Обмен токена на секрет (Bootstrap)

После того как игрок получил токен и ввел его в Standalone-клиенте (или отсканировал QR-код):
1. Standalone-клиент подключается к API моста (TCP или HTTP) и передает токен.
2. Мост проверяет токен. Если он валиден и не просрочен, мост сжигает токен.
3. Мост получает экземпляр внутреннего сервера SVC (используя рефлексию или адаптер версий, так как публичный `VoicechatServerApi#getSecret` возвращает `null`).
4. Мост вызывает внутренний метод `generateNewSecret(uuid)`.
5. Мост отправляет клиенту параметры (`SessionBootstrap`: UUID, Secret, Host, Port, Codec, MTU).
6. Клиент разрывает TCP/HTTP-соединение и начинает стандартный UDP-handshake SVC.

### 4. Интеграция в мир (Виртуальный игрок)

SVC требует, чтобы игрок находился в мире (имел координаты), чтобы работал пространственный звук (Positional Audio).
Если Standalone-клиент подключается *без* запущенного Minecraft-клиента, на сервере нет сущности игрока.
- Для **глобальных групп** это не проблема (звук не позиционируется).
- Для **пространственного звука** мосту в будущем потребуется либо создавать "виртуального" игрока (NPC), либо привязывать аудио к конкретной локации (например, лобби). Текущая реализация ориентирована на глобальные голосовые группы.

## Текущая реализация (Paper Plugin)

В директории `paper-plugin` находится реализация моста, включающая:
- Хранилище одноразовых токенов с тайм-аутами.
- Команду `/voice standalone`.
- Обработчик входа игроков для автоматической генерации токенов.

*Примечание:* Извлечение реального секрета SVC требует рефлексии к внутренним классам Simple Voice Chat, что делает плагин зависимым от конкретной версии SVC.

## Внешний HTTPS relay без дополнительного порта

Для хостингов Minecraft, которые не позволяют открыть дополнительный входящий TCP-порт, создан отдельный Vercel-проект `simple-voice-bootstrap-relay-next`. Он принимает только HTTPS-запросы от клиентов и получает от Paper-плагина только исходящие HTTPS-запросы. Поэтому Minecraft-хостинг не принимает новые входящие соединения.

> Публичный адрес relay: `https://simple-voice-bootstrap-relay-next.vercel.app`

### Обязательные environment variables Vercel

| Переменная | Назначение | Требование |
|---|---|---|
| `UPSTASH_REDIS_REST_URL` | URL приватного Upstash Redis REST endpoint | Не публиковать в коде или клиенте. |
| `UPSTASH_REDIS_REST_TOKEN` | Токен доступа к Upstash Redis | Не публиковать и не записывать в Paper config. |
| `BRIDGE_SERVER_ID` | Идентификатор вашего Minecraft-сервера | Минимум 3 символа, например `my-minecraft-server`. |
| `BRIDGE_SHARED_SECRET` | Общий секрет HMAC между Vercel relay и Paper-плагином | Не менее 32 случайных символов; одинаковый в Vercel и `paper-plugin/config.yml`; не передаётся standalone-клиентам. |

Relay возвращает короткоживущий bootstrap только после атомарного одноразового обмена кода. Redis хранит хеш кода, а не исходный одноразовый код, и удаляет записи по TTL. До настройки этих переменных `GET /api/health` корректно отвечает `503 Service unavailable`.

### Paper config

В `plugins/StandaloneVoiceBridge/config.yml` включите `external-bootstrap.enabled` только после настройки Vercel-переменных. Укажите:

```yaml
external-bootstrap:
  enabled: true
  base-url: "https://simple-voice-bootstrap-relay-next.vercel.app"
  server-id: "my-minecraft-server"
  shared-secret: "тот-же-длинный-случайный-секрет-что-и-в-vercel"
  public-voice-host: "play.example.com"
```

`public-voice-host` — существующий публичный хост вашего SVC UDP-сервера. Он не открывает новый порт. Никогда не помещайте `shared-secret`, Redis credentials, session secret или pairing code в QR-код, лог или Git-репозиторий.

## Ограничение протокольного адаптера

Windows и Android уже умеют отправить одноразовый код в relay и безопасно получить bootstrap. Но передача голоса не будет запущена до успешной проверки версии-специфичного SVC UDP/Opus адаптера на вашем сервере. Клиенты очищают секрет из памяти сразу после текущей проверки, а не выполняют неподтверждённые UDP-пакеты.
